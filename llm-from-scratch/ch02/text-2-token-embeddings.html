2.2 Tokenizing text

class SimpleTokenizerV1:
    def __init__(self, vocab):
        self.str_to_int = vocab
        self.int_to_str = {i:s for s,i in vocab.items()}
    def encode(self, text):
        preprocessed = re.split(r'([,.:;?_!"()\']|--|\s)', text)
        preprocessed = [item.strip() for item in preprocessed if item.strip()]
        ids = [self.str_to_int[s] for s in preprocessed]   # KeyError on unknown words
        return ids

2.4 Adding special context tokens

Fix the KeyError by adding two special entries to the vocab: <|unk|> for any word not seen during training, and <|endoftext|> to mark boundaries between documents. This is SimpleTokenizerV2.

–vocab size (+2 special)

Encode → IDs (unknown words now map to <|unk|> instead of crashing)

Decode(Encode(text)) — round trip

Compare this to your original input above. Every word that wasn't in the training vocab has been permanently replaced by <|unk|> — information is lost. That's the motivation for byte-pair encoding, next.

Show notebook code 
all_tokens = sorted(list(set(preprocessed)))
all_tokens.extend(["<|endoftext|>", "<|unk|>"])
vocab = {token:integer for integer,token in enumerate(all_tokens)}

class SimpleTokenizerV2:
    def encode(self, text):
        preprocessed = re.split(r'([,.:;?_!"()\']|--|\s)', text)
        preprocessed = [item.strip() for item in preprocessed if item.strip()]
        preprocessed = [item if item in self.str_to_int else "<|unk|>" for item in preprocessed]
        return [self.str_to_int[s] for s in preprocessed]

2.5 Byte pair encoding (the real GPT-2 tokenizer)

GPT-2 doesn't use a word-level vocab with <|unk|> at all. Its BPE tokenizer (50,257 tokens) breaks any word — even ones it never trained on — into known subword pieces, so nothing is ever lost. This runs the actual GPT-2 encoding (tiktoken's "gpt2", aka r50k_base) live in your browser.

2.6 Data sampling with a sliding window

2.7 Creating token embeddings

An embedding layer is just a lookup table: one row per vocab id. torch.nn.Embedding(vocab_size, output_dim) creates a vocab_size × output_dim matrix of (initially random) numbers; looking up id k returns row k. GPT-2 really uses a 50,257 × 256 matrix — here's a toy 6 × 3 one you can actually see in full.

The embedding matrix (6 words × 3 dimensions, seeded random)

Look up some ids

Each row above is just copied from the matching row of the matrix — no computation, purely a lookup. That's why the same id always gives the same vector, regardless of where it appears.

Show notebook code 
torch.manual_seed(123)
embedding_layer = torch.nn.Embedding(vocab_size, output_dim)
embedding_layer(torch.tensor([2, 3, 5, 1]))   # -> 4 rows copied from the weight matrix

2.8 Encoding word positions

Token embeddings alone can't tell "the" at position 0 from "the" at position 40 — the lookup is identical either way. GPT-2 fixes this with a second embedding table, indexed by position (0, 1, 2, …), which gets added elementwise to the token embedding.

pos_embedding_layer = torch.nn.Embedding(context_length, output_dim)

input_embeddings = token_embeddings + pos_embeddings   # elementwise add, broadcast over batch
